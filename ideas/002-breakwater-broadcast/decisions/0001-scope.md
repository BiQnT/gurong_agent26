# 0001. 방파제 안내방송으로 범위를 정한 이유

- **날짜**: 2026-08-02
- **상태**: 제안
- **정한 사람**:
- **관련**: [노션 아이디어 보드](https://app.notion.com/p/300d9a77d21883d591fe8171ebf56b27) · [API 카탈로그](../../../docs/api-catalog/06-보행자안전.md)

## 맥락

노션 아이디어 보드에 이미 5개가 올라와 있고, 8월 1주차(~8.9)에 하나로 확정한다.
새 아이디어를 낼 자리는 하나뿐이고, 이번 주 안에 MVP까지 올려야 한다.

제약 세 가지가 범위를 결정했다.

1. **기존 4개와 겹치면 안 된다.** 보드의 나머지는 침수 예측, 연안 해상교통, 과메기
   건조, 배리어프리 내비게이션이다.
2. **이번 주에 만들 수 있어야 한다.** API가 적을수록, 데이터가 이미 가공된 형태로
   나올수록 좋다.
3. **LLM이 장식이면 안 된다.** 요건 3번이 "단순 질의응답을 넘어 판단·추천·경보·시각화"다.
   대시보드로 충분한 아이디어는 챗봇을 얹어도 요건을 억지로 채우는 모양이 된다.

## 결정

**보행자안전 서비스(`INT_S06_*`)를 축으로, AI CCTV가 검출한 이상행동과 기상·자외선
데이터를 읽어 위험을 판단하고, 방파제 스피커로 내보낼 안내방송 문안을 상황에 맞게
생성하는 에이전트**로 범위를 정한다.

MVP는 방송 문안 생성까지다. 실제 스피커 송출은 하지 않는다 — 장비 제어 권한이 없고,
있더라도 대회 범위 밖이다.

## 이유

**스피커가 실재하는 출력 장치다.** `INT_S06_001` 응답에 `speakers` 목록이 있고 장비명이
`구룡포 북방파제 SR-01-001`이다. 대부분의 안전 에이전트는 화면에 경고를 띄우고 끝나는데,
여기는 현장에 소리를 내보내는 액추에이터가 트윈에 이미 붙어 있다.

**그 지점에서 LLM이 필수가 된다.** 방송 문안은 규칙으로 만들 수 없다. 같은 위험도라도
평일 새벽의 조업 어민과 주말 낮의 가족 관광객에게 할 말이 다르고, 외국인이 섞이면
언어가 달라진다. 위험 판단은 규칙으로 하고 **문안 생성만 LLM이 맡는** 구조라 환각이
판단에 끼어들지 않는다.

**영상 분석을 새로 할 필요가 없다.** `INT_S06_006`이 "시간대별 이상행동 발생수 통계"다.
AI CCTV가 이미 검출한 이벤트를 받아 쓰면 된다. 3주 개발 기간에서 이게 결정적이다.

**API가 4개로 끝난다.** `INT_S06_001`(장비 목록 — 자외선기·스피커·AI CCTV가 한 번에),
`INT_S06_005`(자외선 실시간), `INT_S06_006`(이상행동 통계), `INT_S03_019`(기온·풍속·풍향).

## 검토한 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| 위판장 경매 가격 조율 | **E-UM에 위판 가격·물량 데이터가 없다.** `07-수산물유통` 5개 API는 위판장 위치 1개 + 교통 4개가 전부다. 공공데이터로 보충하면 트윈 연동이 곁다리가 된다 |
| 위판장 물류 혼잡 예측 | 데이터는 있으나(`INT_S07_004` 차종별 교통량) 사용자가 자연어로 물어볼 것이 없다. 대시보드로 충분하고 LLM이 장식이 된다 |
| 수산가공 악취 확산 | 구룡포 악취 민원 사례를 뉴스·통계 어디서도 찾지 못했다. 근거 없는 문제로는 지역 기여도(20점)를 못 받는다. 어느 어항에나 있는 일반 문제라 "왜 구룡포인가"에도 답이 안 된다 |
| 과메기 덕장 건조 조건 | 김영재 제안(보드 #2)과 정면으로 겹친다. 산패 위험 지수까지 이미 설계돼 있다 |

## 결과

- **쉬워지는 것**: 쓰는 API가 4개뿐이라 데이터 레이어를 하루면 끝낸다. 이상행동 검출을
  직접 안 해도 된다. 지도 시각화 소재(스피커·CCTV 위치와 커버리지)가 장비 목록 API
  한 번에 다 나온다.
- **감수하는 것**: 주최 측 제시 예시("방파제 보행자/기상 데이터로 위험 접근을 경보하는
  안전 안내 에이전트")와 소재가 겹친다. 차별성은 **경보 자체가 아니라 방송 문안 생성**에
  걸어야 하고, 기획서에서 이 구분을 명시적으로 써야 한다.
- **되돌리려면**: 데이터 레이어(`prototype/eum_client.py`)는 보행자안전 서비스에 한정돼
  있지 않아서, 다른 `INT_S*` 계열로 갈아타도 그대로 쓸 수 있다.

## 아직 안 정한 것

- **위험도 임계값.** 이상행동 발생수 몇 건부터, 풍속 몇 m/s부터 방송을 내보낼지는
  실제 응답 분포를 보고 정한다. `research/api-tests/probe-summary.md`가 나오기 전에
  숫자를 지어내지 않는다.
- **`INT_S06_006`의 "이상행동"이 무엇인지.** 카탈로그에 정의가 없다. 실족·추락인지,
  월파 구간 접근인지, 배회인지에 따라 아이디어의 설득력이 달라진다. 응답을 보고
  모르면 주최 측(권소현)에 문의한다.
