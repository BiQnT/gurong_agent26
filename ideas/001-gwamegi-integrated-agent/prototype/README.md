# 프로토타입

## dry_check_agent.py

사용자의 자연어 질문 → `INT_S01_004`(대기환경 실시간_단일) 실제 호출 →
임계값 기반 건조 적합도 판단 → Claude로 자연어 응답. MVP 3대 요건(LLM 자연어
이해·응답 / 실제 API 호출 / 판단)을 전부 만족하는 최소 스크립트다.

**실행 방법**

```bash
# 저장소 루트에 .env가 없다면 먼저 만든다 (이미 있으면 생략)
cp ../../../.env.example ../../../.env   # EUM_SERVICE_KEY, ANTHROPIC_API_KEY 채우기

pip install -r requirements.txt
python dry_check_agent.py "오늘 오후에 과메기를 널어도 괜찮을까?"
```

`ANTHROPIC_API_KEY`가 비어 있으면 자연어 응답 대신 규칙 기반 판단 결과와 원본 수치만
출력한다 (LLM 연결 전에도 데이터 파이프라인만 먼저 확인할 수 있게 한 것).

`.env`는 저장소 루트 기준으로 한 개만 두면 된다 — 스크립트가 자기 위치부터 상위
디렉터리로 올라가며 `.env`를 자동으로 찾는다 (`python-dotenv`의 `find_dotenv`).

## 주의할 점 두 가지

**1. 판단 기준(임계값)은 검증된 값이 아니라 임의로 정한 값이다.**

`judge_drying_condition()`의 `습도 > 80%`, `풍속 < 1m/s`, `PM10 > 150`은 과메기 산패에 대한
실제 연구·문헌을 조사해서 정한 게 아니라, MVP를 굴려보기 위해 상식적으로 추정한 값이다.

- `PM10 > 150`: 한국 환경부 대기질 등급의 "매우나쁨"(151~) 경계와 얼추 맞춘 값. 다만 이건
  "사람이 숨쉬기에" 안 좋은 기준이지 "과메기가 미세먼지에 노출되면 산패에 얼마나
  영향받는지"에 대한 근거는 아니다
- `습도 > 80%`: 일반적으로 곰팡이·미생물이 번식하기 쉬워지는 습도 구간이라는 일반론에서
  가져온 것으로, 과메기 특이적 기준이 아니다
- `풍속 < 1m/s`: "바람이 없으면 건조가 안 되고 표면에 습기가 남는다"는 상식적 추론이지
  측정된 수치가 아니다

기획서나 발표에 "과학적 기준"인 것처럼 인용하면 안 된다. 실제 과메기/건조수산물 관련
선행 연구(수산과학원 자료, 논문 등)를 찾아 교체하거나, 최소한 "잠정 기준"이라고 명시할 것.
관련 리스크는 [../README.md](../README.md) 9번과 [../data.md](../data.md) "데이터 공백"에도
적어뒀다.

**2. 스크립트가 가져오는 값은 "지금 이 순간"의 실측치가 아닐 수 있다.**

`INT_S01_004`는 이름이 "실시간"이지만, 실제로는 해당 장비(`id=1` 고정)가 **마지막으로
보고한 값**을 준다. `../data.md`의 "측정 간격 및 결측치 관찰"에서 확인한 바로는:

- 장비별로 마지막 보고 시각이 최대 16시간 이상 차이 남
- `id=1` 장비 자체도 한 번은 9시간 전 데이터를 준 적이 있음
- 응답에 포함된 `logDateTime`(측정 시각)을 반드시 같이 확인해서, 오래된 데이터로 판단하고
  있는 건 아닌지 사용자에게 알려줄 필요가 있음 (현재 스크립트는 이 경고를 하지 않는다)
