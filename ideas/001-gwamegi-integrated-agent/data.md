# 구룡포 과메기 통합 에이전트 — 사용 데이터

[API 카탈로그](../../docs/api-catalog/README.md)에서 쓸 API를 고르고, **실제로 호출해본 결과**를 남긴다.
호출해보지 않은 API는 "쓸 예정"으로만 적고 판정란을 비워둔다.

## 요약

| API ID | 엔드포인트 | 호출 테스트 | 판정 |
| --- | --- | --- | --- |
| `INT_S01_001` ⚠ | `/dpg/atmosphere/devices` | 성공 | 사용 (장비 위치 확인용) |
| `INT_S01_004` | `/dpg/atmosphere/device/realtime` | 성공 | 사용 (MVP 필수) |
| `INT_S06_005` | `/dpg/sensor/latest/uvIndex` | 성공 | 사용 (MVP 선택) |

> ⚠ `INT_S01_001`은 E-UM API 자료실 메타데이터에 정식 등록이 안 된 API다. genix 서버에서 직접
> 동작을 확인했다. 상세 조사 기록: [research/api-tests/2026-08-04-atmosphere-undocumented-apis.md](../../research/api-tests/2026-08-04-atmosphere-undocumented-apis.md)

## 호출 기록

### INT_S01_001 — 대기환경 측정 장비 기본 정보 목록_전체 ⚠ (E-UM 자료실 미등록, genix 직접 확인)

**요청**

```bash
curl -s "https://genix.pohang-eum.kr/dpg/atmosphere/devices?serviceKey=$EUM_SERVICE_KEY"
```

**응답 (일부, 전체 24개 장비 중 3개만 발췌)**

```json
{
  "id": "1",
  "status": "success",
  "data": [
    {
      "id": 1,
      "name": "유해물질 측정기 외1",
      "latitude": "35.980946",

      "nickname": "구룡포행정복지센터 남서측"
    },
    {
      "id": 4,
      "name": "유해물질 측정기 외4",
      "latitude": "35.991333",

    {

    }

```

**확인한 것**

- 데이터가 실제로 들어오는가 (빈 배열/null이 아닌가): O — 장비 24개 전체의 위경도·주소가 정상적으로 옴
- 갱신 주기 / 최신 데이터 시각: 장비 메타데이터(위치 정보)라 실시간성과 무관, 변동이 잦지 않을 것으로 추정
- 좌표계, 시간대(KST/UTC), 단위: `latitude`/`longitude`는 WGS84로 추정되는 일반적인 위경도 소수 표기. 시간대 필드 없음
- 구룡포 지역을 커버하는가: **구룡포읍뿐 아니라 호미곶면(대보리, 강사리 등)까지 24개 장비가 분포**. 서비스명("구룡포읍 대기환경")보다 실제 커버리지가 넓음
- 호출 제한이 있는가: 미확인

**막힌 것 / 이상한 것**

- E-UM API 자료실 메타데이터에 정식 등록이 안 된 API다 (카탈로그 조사 경위는 위 링크 참고). 응답의 장비 `id`는 `INT_S01_004`/`INT_S01_003`의 `devId`와 같은 값 체계라 두 API를 연결해 장비별 실시간값+위치를 매칭할 수 있음
- 목록 API(`INT_S01_001`)엔 장비 24개(`id` 1~24)가 전부 나오지만, 실시간 전체 API(`INT_S01_003`)로 같은 시점에 호출했을 땐 `devId=23`이 빠진 23개만 응답했다 — 특정 장비가 일시적으로 데이터를 못 보내는 경우가 있는 것으로 보임. 코드에서 목록 기준으로 순회하되 실시간 응답에 없는 장비는 결측 처리 필요

### INT_S01_004 — 대기환경 측정 장비 실시간 수집 정보_단일

**요청**

```bash
curl -s "https://genix.pohang-eum.kr/dpg/atmosphere/device/realtime?serviceKey=$EUM_SERVICE_KEY&id=1"
```

**응답 (일부)**

```json
{
  "id": "1",
  "status": "success",
  "data": {
    "logDateTime": "2026-08-03 19:48:14",
    "devId": 1,
    "pm10": 14.8,
    "pm25": 13.9,
    "so2": 0.05,
    "no2": 0.001,
    "o3": 0.025,
    "co": 0.391,
    "voc": 0.08,
    "h2s": 0.004,
    "nh3": 0.003,
    "ou": 6.0,
    "hcho": 0.007,
    "co2": 0.0449,
    "temp": 24.4,
    "humi": 83.3,
    "winsp": 0.0,
    "windir": 282.2,
    "batt": 12.4
  }
}
```

**확인한 것**

- 데이터가 실제로 들어오는가 (빈 배열/null이 아닌가): O — `id=1` 장비에서 실측값이 정상적으로 옴
- 갱신 주기 / 최신 데이터 시각: 응답 시점(2026-08-04) 기준 `logDateTime`이 하루 이내(2026-08-03 19:48)라 실시간에 가까움. 정확한 갱신 주기는 반복 호출로 추가 확인 필요
- 좌표계, 시간대(KST/UTC), 단위: 이 응답 자체엔 좌표가 없지만, `devId`로 `INT_S01_001`(장비 목록_전체)과 매칭하면 위경도 확인 가능(아래 참고). 시간대 표기가 없어 KST로 추정되나 미확인. 단위는 카탈로그 문서 기준 PM10/PM2.5는 PPM 표기(단, 실제로는 ㎍/㎥ 관례상 값일 가능성 있어 재확인 필요), 온도 ℃, 습도 %, 풍속 m/s로 추정
- 구룡포 지역을 커버하는가: `INT_S01_001`로 확인한 결과, 구룡포읍뿐 아니라 호미곶면까지 24개 장비가 분포함 (아래 `INT_S01_001` 기록 참고)
- 호출 제한이 있는가: 미확인 (문서에 명시 없음, 반복 호출 테스트 필요)

**막힌 것 / 이상한 것**

- `id` 파라미터가 필수인데, 이 API 하나만 보면 어떤 `id`가 유효한지 알 수 없다. `INT_S01_001`(장비 목록_전체, 아래 참고)로 유효한 `id` 목록(1~24)을 먼저 받아온 뒤 순회하는 방식을 권장
- `pm10`/`pm25` 단위가 카탈로그 문서엔 "PPM"으로 적혀 있는데 대기오염 물질 표기 관례상 "㎍/㎥"가 맞을 가능성이 있음 — 문서 오기일 수 있어 그대로 인용하지 말고 추가 검증 필요

### INT_S06_005 — 자외선 측정 장비 실시간 수집 정보

**요청**

```bash
curl -s "https://genix.pohang-eum.kr/dpg/sensor/latest/uvIndex?serviceKey=$EUM_SERVICE_KEY"
```

**응답 (일부)**

```json
{
  "id": "1",
  "status": "success",
  "data": {
    "dateTime": "2026-08-04 04:40:38",
    "uvIndex": 0.3
  }
}
```

**확인한 것**

- 데이터가 실제로 들어오는가 (빈 배열/null이 아닌가): O — 실측 UV 지수 값이 옴
- 갱신 주기 / 최신 데이터 시각: 호출 시점(2026-08-04) 기준 새벽 4시 40분 데이터 — 이른 아침이라 UV 지수가 낮은(0.3) 건 자연스러움. 반복 호출로 갱신 주기 추가 확인 필요
- 좌표계, 시간대(KST/UTC), 단위: `id` 파라미터 없이 호출해도 성공 — 특정 장비가 아니라 대표값(또는 유일 장비)을 반환하는 것으로 보임. 시간대 표기 없어 KST 추정, 미확인. UV 지수는 단위 없는 지수값
- 구룡포 지역을 커버하는가: 서비스명이 "구룡포읍 보행자안전"이라 구룡포 한정으로 추정. `INT_S06_001`(장비 목록)로 위경도까지 확인은 아직 안 함
- 호출 제한이 있는가: 미확인

**막힌 것 / 이상한 것**

- 없음 — `INT_S01_004`와 달리 `id` 파라미터 없이 바로 성공했다

## 측정 간격 및 결측치 관찰

`INT_S01_001`(장비 목록)과 `INT_S01_003`(실시간_전체)을 시간차를 두고 두 번 호출해서 확인한 내용. 정식 API 문서엔 갱신 주기가 명시돼 있지 않아, 아래는 관찰치이지 보장된 스펙이 아니다.

- **공간 간격**: 대기환경 장비 24개는 구룡포읍~호미곶면에 걸쳐 분포. 가장 먼 두 장비 간 거리 약 **15.3km**. 장비간 최근접 거리는 평균 **약 628m**(최소 73m, 최대 3.1km) — 방파제·위판장 주변은 조밀하고, 호미곶 관광지 쪽은 1대씩 띄엄띄엄 배치된 형태
- **시간 간격**: 같은 시점(2026-08-04 22:31)에 24개 장비를 한 번에 조회했더니 장비별 `logDateTime`이 **05:56~22:31로 최대 16시간 이상 차이**남 — 장비마다 갱신 주기가 다르거나 일부가 오랫동안 갱신이 안 되고 있다는 뜻. 정확한 리포팅 주기(예: 5분/1시간 단위)는 API 응답만으로는 특정할 수 없음
- **결측치**: 등록된 24개 장비 중 실시간 API(`INT_S01_003`) 응답엔 매번 23개만 나옴 — `devId=23`이 서로 다른 시점의 두 호출(2026-08-04 새벽, 22:31) 모두에서 빠짐 (일시적이 아니라 지속적 결측으로 보임). 추가로 `devId=5`, `7`은 응답엔 포함되지만 `logDateTime`이 빈 문자열이라 사실상 신뢰할 수 없는 값 → **24개 중 3개(12.5%)가 매 호출마다 결측/이상 상태**
- MVP 코드에서는 이 결측 장비들을 건너뛰거나 "데이터 없음"으로 표시하는 처리가 필요함

이 아이디어가 성립하려면 필요한데 **어디에도 없는** 데이터. 있으면 솔직히 적고 대안을 쓴다.

| 필요한 데이터 | 없는 이유 | 대안 |
| --- | --- | --- |
| 과메기 산패도와 온습도·풍속·자외선의 정량적 상관관계 기준 | 공식 API가 아니라 별도 선행 연구/실측 자료가 필요한 영역 | MVP는 이 기준 없이 상식적 임계값(습도 80%↑, 풍속 1m/s↓ 등)으로 대체하고, 근거 미확정임을 리스크로 명시 |
