# 구룡포 과메기 통합 에이전트 — 사용 데이터

[API 카탈로그](../../docs/api-catalog/README.md)에서 쓸 API를 고르고, **실제로 호출해본 결과**를 남긴다.
호출해보지 않은 API는 "쓸 예정"으로만 적고 판정란을 비워둔다.

## 요약

| API ID | 엔드포인트 | 호출 테스트 | 판정 |
| --- | --- | --- | --- |
| `INT_S01_004` | `/dpg/atmosphere/device/realtime` | 성공 | 사용 (MVP 필수) |
| `INT_S06_005` | `/dpg/sensor/latest/uvIndex` | 성공 | 사용 (MVP 선택) |

## 호출 기록

### INT_S01_004 — 대기환경 측정 장비 실시간 수집 정보_단일

**요청**

```bash
curl -s "https://genix.pohang-eum.kr/dpg/atmosphere/device/realtime?serviceKey=$EUM_SERVICE_KEY&id=1"
```

**응답 (일부)**

```json
{
  "id": "1",
  "status": "success",
  "data": {
    "logDateTime": "2026-08-03 19:48:14",
    "devId": 1,
    "pm10": 14.8,
    "pm25": 13.9,
    "so2": 0.05,
    "no2": 0.001,
    "o3": 0.025,
    "co": 0.391,
    "voc": 0.08,
    "h2s": 0.004,
    "nh3": 0.003,
    "ou": 6.0,
    "hcho": 0.007,
    "co2": 0.0449,
    "temp": 24.4,
    "humi": 83.3,
    "winsp": 0.0,
    "windir": 282.2,
    "batt": 12.4
  }
}
```

**확인한 것**

- 데이터가 실제로 들어오는가 (빈 배열/null이 아닌가): O — `id=1` 장비에서 실측값이 정상적으로 옴
- 갱신 주기 / 최신 데이터 시각: 응답 시점(2026-08-04) 기준 `logDateTime`이 하루 이내(2026-08-03 19:48)라 실시간에 가까움. 정확한 갱신 주기는 반복 호출로 추가 확인 필요
- 좌표계, 시간대(KST/UTC), 단위: 응답에 좌표는 없음(장비 목록 API가 따로 없어 위경도 미확인). 시간대 표기가 없어 KST로 추정되나 미확인. 단위는 카탈로그 문서 기준 PM10/PM2.5는 PPM 표기(단, 실제로는 ㎍/㎥ 관례상 값일 가능성 있어 재확인 필요), 온도 ℃, 습도 %, 풍속 m/s로 추정
- 구룡포 지역을 커버하는가: 서비스명 자체가 "구룡포읍 대기환경"이라 대상 지역은 구룡포로 한정됨. 다만 장비의 정확한 위치(위경도)는 카탈로그에 목록 API가 없어 확인 못함
- 호출 제한이 있는가: 미확인 (문서에 명시 없음, 반복 호출 테스트 필요)

**막힌 것 / 이상한 것**

- `id` 파라미터가 필수인데, 대기환경 서비스에는 장비 목록을 조회하는 API가 카탈로그에 없다. `id=1`로 시도해 성공했지만, 이게 구룡포 내 유일한 장비인지 여러 장비 중 하나인지 확인이 안 됨 → E-UM 포털 지도 화면 확인 또는 담당자(권소현) 문의 필요
- `pm10`/`pm25` 단위가 카탈로그 문서엔 "PPM"으로 적혀 있는데 대기오염 물질 표기 관례상 "㎍/㎥"가 맞을 가능성이 있음 — 문서 오기일 수 있어 그대로 인용하지 말고 추가 검증 필요

### INT_S06_005 — 자외선 측정 장비 실시간 수집 정보

**요청**

```bash
curl -s "https://genix.pohang-eum.kr/dpg/sensor/latest/uvIndex?serviceKey=$EUM_SERVICE_KEY"
```

**응답 (일부)**

```json
{
  "id": "1",
  "status": "success",
  "data": {
    "dateTime": "2026-08-04 04:40:38",
    "uvIndex": 0.3
  }
}
```

**확인한 것**

- 데이터가 실제로 들어오는가 (빈 배열/null이 아닌가): O — 실측 UV 지수 값이 옴
- 갱신 주기 / 최신 데이터 시각: 호출 시점(2026-08-04) 기준 새벽 4시 40분 데이터 — 이른 아침이라 UV 지수가 낮은(0.3) 건 자연스러움. 반복 호출로 갱신 주기 추가 확인 필요
- 좌표계, 시간대(KST/UTC), 단위: `id` 파라미터 없이 호출해도 성공 — 특정 장비가 아니라 대표값(또는 유일 장비)을 반환하는 것으로 보임. 시간대 표기 없어 KST 추정, 미확인. UV 지수는 단위 없는 지수값
- 구룡포 지역을 커버하는가: 서비스명이 "구룡포읍 보행자안전"이라 구룡포 한정으로 추정. `INT_S06_001`(장비 목록)로 위경도까지 확인은 아직 안 함
- 호출 제한이 있는가: 미확인

**막힌 것 / 이상한 것**

- 없음 — `INT_S01_004`와 달리 `id` 파라미터 없이 바로 성공했다
