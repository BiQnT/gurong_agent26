# 2026-10-10 · 기상청 초단기실황 격자 값으로 판정 ([ADR 0013](../../docs/decisions/0013-distance-tiered-observation.md))

1km 안 E-UM 과 5km 안 기상청 AWS 가 없을 때 덕장이 속한 초단기실황 5km 격자의 기온·습도·풍속으로 판정하기 전에, 로컬 `.env.local` 의 `KMA_AUTH_KEY` 로 실제 호출했다. 키와 키가 든 URL 은 기록하지 않는다. `2026-10-10T03:47Z` (12:47 KST), 로컬.

## 읽는 법

- 항목마다 `baseDate`·`baseTime`(발표 정시)·`nx`·`ny`·`category`·`obsrValue`(글). 서버는 T1H·REH·WSD 를 숫자로 읽고, 없는 항목이나 빈 값은 0 이 아니라 없음으로 둔다 (`readNowcastGrid`).
- 매시 자료가 약 40분 뒤 나온다. 서버는 45분 전 시각의 정시를 묻고 다음 자료가 나올 때까지 쓰므로 정시 기준 최대 약 105분 지난 값을 받는다. 그래서 격자 값은 2시간까지 최신으로 본다 (`GRID_STALE_MINUTES`).
- **격자 값은 분석값이다.** 바로 옆 격자 105,94 와 105,92 가 같은 값을 줬다. 주변 관측으로 만든 값이라 덕장 현장과 다를 수 있어, 실제 관측인 AWS 를 먼저 쓰고 격자 판정에는 그렇게 밝힌다.
- 비·눈 확인(PTY·RN1)과 같은 호출이라 격자 관측을 더해도 기상청 호출 수는 늘지 않는다.
- 덕장과의 거리는 격자 중심까지 잰다. 격자 → 좌표는 기상청 격자 변환의 역변환이고, 5km 격자라 격자 안 어느 점도 중심에서 약 3.6km 안이다.

## 같은 날 AWS 816 상태 (판정 순서 2번)

로컬 서버로 구룡포 AWS 에서 약 2.9km 떨어진 덕장을 물었더니 AWS 대신 격자로 판정했다. 직접 확인한 원인 (`2026-10-10T07:3xZ`, 16:3x KST):

| 확인 | 결과 |
| --- | --- |
| `nph-aws2_min` (최근 10분, stn=816) 세 번 | 8.0초 응답 없음, 30.4초 응답 없음, 4.5초 HTTP 200. 서버는 한 번에 4초씩 두 번까지만 기다린다 |
| HTTP 200 응답의 마지막 6줄 | 기온·습도는 정상(23.9°C, 71.9%), **WS10(10분 평균 풍속, 7번째 칸)이 모든 줄에서 -99.9**, WS1(1분 평균 풍속, 3번째 칸)은 1.8~2.7m/s |

풍속이 비면 그 관측은 판정에 못 쓰는 값(`invalid`)이 되어 격자로 넘어갔다. 서버는 이제 WS10 이 비면 WS1 을 쓰고, 마지막 줄 가운데 세 값이 다 있는 줄을 먼저 고른다 (`awsWind`). API허브가 멈추는 것은 2026-10-06·09 기록과 같아서, 그때는 규칙대로 격자로 판정한다.
