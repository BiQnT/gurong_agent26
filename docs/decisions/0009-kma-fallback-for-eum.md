# 0009. E-UM 을 정본으로 두고 기상청 AWS 816 을 대체·교차 확인에 쓴다

- **날짜**: 2026-10-06
- **상태**: 확정
- **정한 사람**: 안동현
- **관련**: [chat-api.md 기상청 보조](../design/chat-api.md#기상청-보조), [호출 기록](../../research/api-tests/2026-10-06-kma-apihub.md)

## 맥락

E-UM 대기환경 관측기는 장비마다 상태가 고르지 않다. 2026-10-06 VM 조회에서 24개 중 18개만 최근 값이었고, 덕장 가까운 장비가 오래된 값을 주는 때가 있다. E-UM 이 막히면 서버는 보관된 과거 실측만 보여 줄 수 있어 실시간 근거가 사라진다.

기상청 AWS 816 구룡포는 1분마다 갱신되고, 예시 덕장에서 약 0.7km 라 덕장 1km 기준 안에 든다. 같은 날 API허브로 실제 호출을 확인했다. 대회 필수 조건은 디지털 트윈(E-UM) 데이터의 실제 호출·활용이다.

## 결정

- E-UM 을 정본으로 둔다. 덕장 1km 안에 최근 E-UM 값이 있으면 화면·AI 근거·30분 수집기 모두 E-UM 을 쓴다.
- 1km 안에 최근 E-UM 값이 없을 때만 기상청 AWS 816 값을 대신 쓰고, 화면과 AI 설명에 기상청 출처를 밝힌다. 배치 기록에도 장비 ID `kma-aws-816` 으로 남는다.
- 둘 다 최근 값이면 비교해, 기온 5°C·습도 25% 넘게 다르면 관측기 상태를 확인하라고 알린다.
- 기상청 초단기실황(비·눈), AWS 강수량, 천문연 일출·일몰은 판정이 아닌 참고 정보로 덕장 관측과 AI 근거에 붙인다.

## 검토한 대안

- **기상청은 나란히 보여 주기만**: 배치 기록과 AI 근거가 E-UM 상태에 묶여 결측이 늘어난다.
- **기상청을 정본으로**: 값은 안정적이지만 디지털 트윈 데이터 활용이 약해 보인다.

## 결과

- E-UM 이 오래됐거나 막혀도 덕장 1km 안의 실시간 관측이 남는다.
- 비교 경고로 E-UM 장비 이상을 알아챌 수 있다. 5°C·25% 는 장비 이상을 거르는 값이며 건조 기준이 아니다.
- API허브가 가끔 응답 없이 멈춰 4초 뒤 한 번 더 부르고, 관측 응답은 기상청을 최대 5초만 기다린다.
