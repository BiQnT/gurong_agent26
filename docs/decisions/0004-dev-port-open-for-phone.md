# 0004. dev 포트(3001)도 외부에 열어 폰으로 UI 를 확인한다

- **날짜**: 2026-10-04
- **상태**: 대체됨 (→ [0005](0005-merge-backend-into-haepung-app.md))
- **정한 사람**: 안동현
- **관련**: [0002](0002-gcp-runtime-layout.md) 의 "dev 는 127.0.0.1" 부분을 바꾼다, [infra/gcp/README.md](../../infra/gcp/README.md)

## 맥락

0002 에서는 dev 서버(`next dev`, 3001)를 VM 안에서만 열고 SSH 터널로 보게 했다.
팀의 의도는 "포트로 개발과 배포를 나누고, 개발 화면은 폰으로도 바로 본다"였다.
현장(덕장) 사용을 전제로 한 모바일 화면이라 폰 확인이 개발 흐름에 들어간다.

## 결정

- dev 를 `0.0.0.0:3001` 로 띄운다. prod 와 같은 접속 암호(BASIC_AUTH)를 건다.
- Next 16 의 `next dev` 는 localhost 가 아닌 주소에서 오는 개발용 요청을 막으므로,
  서버 IP 를 `allowedDevOrigins` 에 넣는다 (dev 유닛의 `DEV_ALLOWED_ORIGINS`).
- 주최 측 방화벽 요청에 3001 을 3000 과 함께 넣는다.

## 이유

- SSH 터널은 폰에서 쓰기 어렵다.
- 2026-10-04 로컬 확인: `allowedDevOrigins` 가 없으면 다른 주소에서 온 `/_next/webpack-hmr` 요청이 403
  ("Blocked cross-origin request")이고, 넣으면 통과한다.

## 검토한 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| dev 는 터널로만, 폰 확인은 prod 배포 후 | 화면 하나 고칠 때마다 배포해야 한다 |
| 폰도 SSH 터널 앱 사용 | 팀원마다 설정이 필요하고 번거롭다 |

## 결과

- 쉬워지는 것: 저장하면 바로 반영되는 dev 화면을 폰으로 확인
- 감수하는 것: 개발 서버(`next dev`)가 인터넷에 노출된다. 암호로 막지만 HTTP 라 평문이고, 개발 서버는 운영용보다 느리고 오류 화면에 코드 일부가 보인다. 외부 사람에게는 prod 주소만 준다
- 되돌리려면: dev 유닛을 `-H 127.0.0.1` 로 바꾸고 bootstrap 재실행
