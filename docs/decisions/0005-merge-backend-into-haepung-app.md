# 0005. 백엔드를 팀원의 해풍 앱 서버에 합치고 화면의 API 계약을 정본으로 둔다

- **날짜**: 2026-10-04
- **상태**: 확정
- **정한 사람**: 안동현
- **관련**: [0002](0002-gcp-runtime-layout.md)·[0004](0004-dev-port-open-for-phone.md)를 대체하고 [0003](0003-claude-cli-wrapper.md)을 일부 대체한다, [docs/design/backend.md](../design/backend.md), [infra/gcp/README.md](../../infra/gcp/README.md)

## 맥락

코드가 두 갈래로 자라 있었다.

| 갈래 | 위치 | 가진 것 |
| --- | --- | --- |
| 백엔드 | `prototype/` (Next.js) | claude CLI 래핑 채팅(SSE), E-UM MCP 도구, 대화 저장 SQLite, VM 배포 스크립트 |
| 팀원 앱 | `src/`, `server/` (Vite + React) | 계정·덕장·초대·작업 기록 화면과 API, 권한·초대·작업 검증과 테스트, OpenAI 호환 LLM, localhost 전용 연결 계층 |

두 갈래의 API 계약이 달랐다. 프로토타입은 `POST /api/chat` 이 SSE 로 답하고 대화 id 를 서버가 관리한다.
화면은 `{ message, siteId, history }` 를 보내 완성된 JSON 을 한 번에 받고, 대화는 브라우저 저장소에 두며,
모든 요청이 로그인한 계정의 덕장 소속 검사를 거친다. 제품은 화면을 가진 쪽이다.

운영 환경도 바뀌었다. 옛 VM(디스크 10GB)을 더 쓰지 않고 새 VM(메모리 1.9GB, 스왑 없음, 디스크 296GB)으로 옮긴다.
새 VM 의 `/srv/haepung` 에는 팀원이 이미 앱을 올려 두었다. 폰으로 prod 와 dev 를 모두 써야 한다.

## 결정

**화면이 쓰는 API 계약([관측·채팅](../design/chat-api.md), [계정·작업](../design/workspace-api.md))을 정본으로 지키고,
백엔드를 팀원의 서버 계층(`server/`)에 합친다.** `prototype/` 은 삭제한다.

합치는 것:

- 공유 SQLite 문서 저장소. dev·prod 가 같은 DB 파일(`DATABASE_PATH`)을 쓴다. 쓰기는 동기 함수만, 저장 전 검증, schema 번호 확인.
- claude CLI 제공자(`LLM_PROVIDER=claude`). 서버가 관측 근거를 확보해 시스템 프롬프트로 주고 claude 는 도구 없이 설명만 한다.
- 운영 서버 `node server/main.ts`. 빌드한 화면(`dist/`)과 API 를 한 포트에서 준다.
- 원격 접속. 허용 출처 목록 `PUBLIC_ORIGINS` 와 전체 출처(스킴·호스트·포트)가 같을 때만 통과, 쿠키 `Secure`(`COOKIE_SECURE`), 로그인 실패 제한(429 `LOGIN_RATE_LIMITED`).
- `/api/health` 가 저장소를 읽고 `commit`·`schema` 를 돌려준다. 읽지 못하면 503 이라 배포가 자동으로 되돌아간다.

버리는 것: E-UM MCP 도구, SSE 응답 계약, 서버 쪽 대화 저장과 `--resume`(대화는 화면이 `history` 로 보낸다).

0003 에서 **유지하는 것**은 claude 실행 제한이다. 내장 도구와 MCP 를 끄고, 서버 계정의 개인 설정을 읽지 않고,
빈 작업 폴더에서 띄우고, 구독 토큰과 API 키를 환경변수 하나로 바꾼다. 메시지당 비용·시간·동시 실행·24시간 비용 상한도 이어진다.

새 VM 배치:

- 서비스 계정과 폴더는 `/srv/haepung`. Caddy 가 TLS 를 맡아 443(prod)과 440(dev)을 받고 80 은 443 으로 넘긴다.
- 앱은 127.0.0.1 에만 연다. prod 는 3000, dev(Vite)는 3001.
- dev 는 공개된 Vite 가 저장소 파일을 그대로 주므로 접속 암호(HTTP Basic)를 건다. prod 는 앱 로그인만 쓴다.
- 가입은 제한하지 않는다.

## 이유

- 화면 계약을 바꾸면 화면 코드와 테스트를 모두 고치고 팀원 확인을 받아야 한다. 서버를 합치는 쪽은 화면을 건드리지 않는다.
- 화면이 요구하는 것(덕장별 권한, 초대, 작업 기록의 revision 충돌 처리, 관측 근거 JSON)은 프로토타입에 없다.
  프로토타입에만 있는 것(SSE, MCP, 서버 대화 저장)은 화면이 쓰지 않는다. 화면은 완성된 답변을 한 번에 받는다.
- 판정은 코드가 하고 생성형 AI 는 설명만 한다는 기획서의 분리에 맞다. 서버가 근거를 확보해 주면
  화면의 관측 카드와 AI 설명이 같은 자료에서 나오고, 모델이 E-UM 을 직접 부를 이유가 없다.
- VM 메모리가 1.9GB 이고 스왑이 없다. 상시 프로세스는 prod 와 dev 둘뿐이고, 수집기와 claude 는 필요할 때만 뜨는 프로세스다.
- dev 와 prod 가 같은 DB 를 쓰므로 파일 저장으로는 안 된다. 프로세스 사이 잠금이 SQLite 의 쓰기 잠금으로 해결된다.

## 검토한 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| `prototype/` 을 유지하고 화면을 프로토타입 계약에 맞춰 고친다 | 계정·덕장·작업 기록 흐름을 프로토타입에도 구현하거나 화면이 서버 둘을 불러야 한다. 화면 코드와 테스트를 다 고치고 팀원 확인을 받아야 한다 |
| 팀원 서버 로직(인증·권한·초대·작업 검증)을 Next.js 로 다시 쓴다 | 테스트가 있는 로직을 옮기면 동작이 달라질 위험만 생긴다. 화면이 Vite 단일 페이지 앱이라 Next.js 의 서버 렌더링도 쓰지 않는다 |
| `.local-data/workspace.json` 파일 저장을 그대로 쓴다 | 쓰기 직렬화가 한 Node 프로세스 안에서만 된다. dev 와 prod 가 같은 파일에 쓰면 서로의 변경을 덮어쓴다 |

## 결과

- 쉬워지는 것: 화면 변경 없이 서버를 배포한다. dev 와 prod 가 같은 권한 로직과 같은 데이터를 쓴다. 제공자를 더하려면 `AgentAsk` 함수 하나(`server/claude-cli.ts`의 모양)를 만들면 된다.
- 어려워지는 것 / 감수하는 것:
  - `server/` 의 변경은 화면과 계약이 맞는지 같이 봐야 한다.
  - 가입을 제한하지 않으므로 한 사람이 AI 사용 한도를 다 쓸 수 있다. 메시지당 비용, 24시간 비용, 동시 실행 상한으로 막는다.
  - dev 의 실수가 공유 DB 로 prod 에 닿는다. 저장 형식을 바꾸는 작업은 dev 를 복사본 DB 로 돌린다.
  - 대화가 브라우저에만 있어 다른 기기에서 이어 볼 수 없다.
  - 이메일 확인과 비밀번호 재설정 메일이 없다. 계정 복구는 관리 스크립트로 한다.
- 되돌리려면: 계약 문서가 그대로라 저장소와 제공자는 `server/` 안에서 바꿀 수 있다.
  삭제한 `prototype/` 은 이 결정의 커밋 직전까지의 git 이력에 남아 있다.
