# 0013. 1km 안 E-UM 이 없으면 거리 순서로 기상청 AWS(5km)와 덕장 격자 초단기실황을 판정에 쓴다

- **날짜**: 2026-10-10
- **상태**: 확정
- **정한 사람**: 안동현
- **관련**: [0009](0009-kma-fallback-for-eum.md)(E-UM 정본, 기상청 보조)와 [0010](0010-drying-grade-rules.md)(1km 거리 게이트)를 바꾼다, [0006](0006-shared-db-validation-order.md)(저장 규칙을 넓힘), [호출 기록](../../research/api-tests/2026-10-10-kma-grid-nowcast.md), [src/lib/drying.ts](../../src/lib/drying.ts), [server/site-observations.ts](../../server/site-observations.ts)

## 맥락

0010 은 덕장에서 1km 안의 최근 관측만 판정에 쓰고, 없으면 판정 불가로 두었다. 기상청 구룡포 AWS(816)도 1km 안일 때만 E-UM 을 대신했다. 실제로 쓰다 보니 덕장이 E-UM 관측기와 AWS 에서 조금만 떨어져도 판정 불가가 되어 "오늘 널어도 되나"에 답하지 못했다. 팀장 판단: 1km 밖이면 E-UM 대신 AWS 등을 써서 거리 순서대로 판단한다.

E-UM 대기환경 관측기는 구룡포읍에 몰려 있고, 기상청 AWS 는 구룡포에 816 하나가 있다. 기상청 초단기실황은 전국 5km 격자마다 기온(T1H)·습도(REH)·풍속(WSD)을 매시 준다. 이미 비·눈 확인에 같은 호출을 쓰고 있었고 2026-10-10 에 세 지점(예시 덕장, 9km 남쪽, 포항 시내)에서 모두 HTTP 200 으로 세 값을 받았다.

## 결정

관측을 거리 순서로 고른다. (1) 1km 안의 믿을 만한 최근 E-UM 관측(정본), 없거나 이상하면 (2) 5km 안의 최근 기상청 AWS, 그것도 없으면 (3) 덕장이 속한 기상청 초단기실황 5km 격자, 셋 다 없으면 판정 불가. 등급 규칙과 기준값은 그대로 두고, 판정 카드와 AI 답에 출처(기상청 AWS·격자)와 거리를 함께 밝힌다. 격자 값은 매시 자료라 2시간까지 최신으로 보고, 30분 자동 기록에도 같은 순서를 쓴다.

## 이유

- **"판정 불가"보다 근거를 밝힌 판정이 쓸모 있다.** 덕장 주인은 판정 불가를 받으면 결국 감으로 정한다. 출처와 거리를 함께 보여 주면 얼마나 믿을지는 사람이 정할 수 있다.
- **실제 관측이 분석값보다 먼저다.** AWS 는 1분마다 재는 실제 관측이고, 초단기실황 격자는 주변 관측으로 만든 분석값이다. 2026-10-10 호출에서 이웃 격자 105,94 와 105,92 가 같은 값을 줬다. 그래서 AWS 를 격자보다 먼저 쓰고, 격자 판정에는 "현장과 다를 수 있다"를 붙인다.
- **5km 는 격자 크기와 같다.** 격자 값도 5km 단위라, 그보다 먼 AWS 를 쓸 이유가 없다. 구룡포읍 덕장은 AWS 816 에서 대부분 5km 안이다.
- **새 API 를 늘리지 않는다.** 둘 다 이미 호출 성공을 확인한 자료다. 격자 관측은 비·눈 확인과 같은 호출을 나눠 써서 기상청 호출 수도 늘지 않는다.
- **E-UM 이 정본인 것은 그대로다.** 1km 안에 믿을 만한 E-UM 이 있으면 기상청이 더 가까워도 E-UM 을 쓴다. E-UM 장비 이상을 가리는 교차 확인(0009, 0010)도 1km 안 AWS 와만 한다.

## 검토한 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| 1km 판정 불가 유지 | 실제 사용에서 판정 불가가 잦아 핵심 질문에 답하지 못한다 |
| 구룡포 AWS 를 거리 제한 없이 | 구룡포에서 먼 덕장도 구룡포 값으로 판정해 틀릴 수 있다 |
| 전국에서 가장 가까운 AWS | 전 지점 매분자료 호출을 새로 검증해야 하고 3주 일정에 비해 크다. 격자 실황으로 전국을 덮을 수 있다 |
| 1km 밖 자료면 적합을 주의로 낮춤 | 팀장 판단으로 같은 규칙을 쓰고 출처를 밝히기로 했다. 낮추면 적합이 거의 나오지 않는다 |

## 결과

- 쉬워지는 것: 구룡포에서 조금 떨어진 덕장도 판정·자동 기록을 받는다. 기상청 키만 있으면 전국 어느 덕장도 판정이 나온다.
- 감수하는 것: 1km 밖 판정은 덕장 바로 옆 관측보다 덜 정확하다. 격자 판정은 매시 값이라 30분 자동 기록에서 한 시간에 한 번만 쌓인다(같은 값은 다시 쌓지 않는다). 기상청 키가 없으면 지금처럼 1km 안 E-UM 만 쓴다.
- 저장 규칙을 넓혔다: 안내 근거(`validFacts`)와 화면 검증(`readAssessment`)의 판정 거리 상한이 1km 에서 5km 로. 이 상한은 판정 기준과 따로 둔 상수(`STORED_GRADED_MAX_DISTANCE_M`)라 기준을 바꿔도 저장 규칙은 그대로다. 0006 에 따라 머지 직후 prod 배포까지 한 번에 한다.
- 구룡포 AWS 의 강수량 안내는 그 AWS 가 5km 안인 덕장에만 붙인다. 먼 덕장은 격자 실황의 비·눈만 본다.
- AWS 10분 평균 풍속(WS10)이 비면 1분 평균(WS1)을 쓴다. 2026-10-10 에 WS10 이 모두 비어 AWS 를 통째로 못 쓰는 일이 있었다. 1분 평균은 10분 평균보다 출렁여 풍속 기준(2m/s, 14m/s) 판정이 조금 더 흔들릴 수 있다.
- 기준 이름을 `2026-10-10 가설값`으로 올렸다. 그 전 판정은 기록에 남은 옛 이름으로 구분된다.
- 되돌리려면: `DRYING_THRESHOLDS.maxFallbackDistanceM` 을 1000 으로, `attachSiteContext` 에 격자를 넘기지 않으면 0010 의 판정 동작으로 돌아간다. `STORED_GRADED_MAX_DISTANCE_M` 은 줄이지 않는다 (이미 저장된 1~5km 판정을 거부하면 prod 가 멈춘다).
