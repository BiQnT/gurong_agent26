# 결정 기록 (ADR)

중요한 결정 하나 = 파일 하나. **한 번 쓴 ADR은 고치지 않는다.**
결정이 뒤집히면 새 ADR을 쓰고, 옛 ADR 맨 위 상태를 `대체됨 (→ NNNN)`으로 바꾼다.

## 왜 이 형식인가

"현재 구조는 이렇다"는 서술형 문서는 시간이 지나면 반드시 틀려진다.
반면 "2026-08-09에 이렇게 정했다"는 기록은 시간이 지나도 틀리지 않는다.

**stale이 될 수 없는 형식으로 적는 것**이 문서 관리의 핵심이다.
ADR은 과거 시점의 사실이라 낡지 않는다. 뒤집힌 결정도 "그때는 그렇게 봤다"는
기록으로서 여전히 옳고, 실제로 기획서의 "검토한 대안" 항목에 그대로 쓸 수 있다.

## 언제 쓰나

쓴다:

- 되돌리기 비싼 선택 (사용할 API, 프레임워크, 배포 방식, 에이전트 구조)
- 나중에 "왜 이렇게 했지?"를 물을 만한 것
- 대안이 여럿이었고 하나를 골랐을 때
- 심사위원이 물어볼 만한 것

안 쓴다:

- 코드를 보면 자명한 것
- 취향 문제 (들여쓰기, 파일명)
- 되돌리기 싼 것

## 쓰는 법

```bash
cp docs/decisions/_template.md docs/decisions/0002-<slug>.md
```
