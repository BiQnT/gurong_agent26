# 0011. AI 도우미는 읽기 전용 도구로 필요한 자료만 보고, 카드는 본 자료로 정한다

- **날짜**: 2026-10-09
- **상태**: 확정
- **정한 사람**: 안동현
- **관련**: [노션 1차 QA](https://app.notion.com/p/3f2d9a77d21880f08bece1de93938f6b), [0005](0005-merge-backend-into-haepung-app.md)의 "claude 는 도구 없이 설명만"을 바꾼다, [0010](0010-drying-grade-rules.md)의 예보·AI 대조 일부를 바꾼다, [chat-api.md](../design/chat-api.md), [server/prompts/](../../server/prompts/)

## 맥락

1차 QA(2026-10-08)에서 AI 도우미가 무엇을 물어도 널기 등급부터 말했다. "팀에 몇 명?"에도 "판정 불가"와 판정·관측 카드 두 장이 붙었고, "그럼 언제 작업하는 게 좋을까?"에는 "판정 불가라 정할 수 없다"로 끝났다. 원인은 셋이었다.

- 기본 지시가 "첫 문장에 assessment.grade 를 그대로 말하라"고 조건 없이 시켰다 (`server/chat.ts` 의 문자열 상수).
- 서버가 질문과 상관없이 모든 답에 판정과 관측을 실어 화면이 매번 카드 두 장을 그렸다.
- AI 가 받는 자료가 현재 관측과 최근 배치 5개 요약뿐이었다. 덕장·팀 정보, 과거 날씨, 예보별 판단이 없었다.

팀은 다음 단계로 일반 Claude·GPT 와 정확도를 비교하려 하고, 그러려면 "과거 데이터로 분석해줘" 같은 요청도 실제 자료로 답해야 한다.

## 결정

- claude CLI 에 **이 덕장 범위의 읽기 전용 도구 6개**를 준다: 현재 상태(`get_current_conditions`), 덕장·팀(`get_site_overview`), 배치 기록(`get_batches`), 과거 기간(`get_weather_history`), 기간 비교(`compare_periods`, 신청서 US-4 의 항목별 편차와 비교 불가 처리), 예보 예상 등급(`get_forecast_outlook`). 도구는 코드가 계산한 결과만 돌려준다. AI 는 어떤 도구를 부를지 고르고 설명만 쓴다.
- 도구는 서버 프로세스 안에서 127.0.0.1 임의 포트로 여는 MCP(Streamable HTTP, JSON 응답) 엔드포인트로 준다. 채팅 요청마다 일회용 토큰을 만들고 요청이 끝나면 지운다. 토큰은 claude 의 환경변수로만 넘긴다. 내장 도구는 지금처럼 모두 끈다.
- **화면 카드는 AI 가 실제로 부른 도구로 정한다.** 현재 상태 도구를 불렀을 때만 판정 카드가 붙는다. 의도를 정규식으로 추측하지 않는다 (AI 를 못 쓸 때의 대체 답만 예외).
- 판정 카드와 관측 카드를 하나로 합치고, 카드를 답 문장 위에 둔다 (QA A·C).
- 기본 지시는 `server/prompts/*.md`(페르소나·규칙·도구 쓰는 법·자료 읽는 법·과메기 상식)로 나눠 PR 로 리뷰한다. 과메기 상식은 출처가 있는 문장만 둔다.
- 예보 시간마다 같은 규칙 함수로 **예상 등급**을 매겨 보여 준다. 현재 등급은 지금처럼 관측으로만 정한다 (0010 의 "예보는 조언으로만"을 바꾼다).
- AI 답 검사를 둘로 나눈다.
  - 등급 대조는 **현재 시점 문장에만** 한다. 과거·예보 문장의 다른 등급은 어긋남이 아니다 (0010 의 "AI 답의 등급 대조"를 좁힌다). 현재 관측을 보지 않고 지금 널어도 된다고 하거나 안전을 보장하면 지금처럼 바꾼다.
  - 새로 **숫자 근거 검사**를 둔다. 답의 측정 숫자(°C·%·m/s·mm)가 같은 단위의 근거(이번 질문의 도구 결과, 기준값, 지시문에 단위와 함께 적힌 값, 사용자가 쓴 숫자)에 없으면 도구가 만든 요약 문장으로 바꾼다.
- "기준은 가설값", "화면에서 승인 후 저장" 같은 고정 문구는 카드와 버튼에 두고 답 문장에서는 물을 때만 말한다.
- 채팅 경로 제한을 45초에서 90초로, claude 기본 시간 제한을 40초에서 75초로 늘린다 (도구 왕복).

## 이유

- 2026-10-09 로컬 claude CLI 2.1.295 로 확인했다. `--tools ''`·`--strict-mcp-config`·`--setting-sources ''` 를 그대로 둔 채 `--mcp-config`(HTTP, 헤더의 `${HAEPUNG_TOOL_TOKEN}` 를 환경변수로 풀어 씀)와 `--allowedTools mcp__haepung` 을 주면 우리 도구만 불렀다. 팀 인원 질문 한 번에 3.9초, 0.006달러였다.
- 실제 E-UM 관측과 claude(sonnet, medium)로 12문항을 돌렸다. 팀·사용법·범위 밖 질문에는 카드 없이 답했고, 널기 질문에만 판정 카드가 붙었다. 응답은 3~6초였다.
- 신청서의 역할 분담("등급 판정·편차는 코드, 생성형 AI 는 의도 파악과 설명")과 맞는다. 의도 파악을 AI 가 하고, 숫자는 도구가 계산하고, 검사기가 다시 본다.
- 0003·0005 에서 버린 MCP 는 E-UM 원본 응답을 그대로 주는 도구였고, 별도 서버 프로세스였다. 이번 도구는 계산된 결과만 주고, 앱 서버 안의 루프백 엔드포인트라 프로세스가 늘지 않는다 (VM 메모리, 동시 실행 2개 유지).

## 검토한 대안

| 대안 | 왜 안 골랐나 |
| --- | --- |
| 미리 담기: 서버가 최근 7일·배치·덕장 정보를 늘 프롬프트에 넣는다 | 단순하고 빠르지만 "작년 12월", "두 기간 비교" 같은 임의 기간을 못 한다. 질문과 무관한 자료를 늘 넣어 다시 아무 때나 등급을 말하게 된다 |
| 정규식으로 의도를 나눠 자료·카드 결정 | 말투가 조금만 달라도 틀린다. 신청서는 의도 파악을 AI 에게 맡겼다 |
| claude 를 두 번 부르기 (계획 → 서버 조회 → 답) | 프로세스 두 개, 시간·비용 두 배 |
| `@modelcontextprotocol/sdk` 로 MCP 서버 | 쓰는 메서드가 4개뿐이라 직접 처리가 짧다. 의존성을 늘리지 않는다 |
| stdio MCP 서버 | claude 마다 node 프로세스가 하나 더 뜬다 (VM 메모리) |

## 결과

- 쉬워지는 것: 질문에 맞는 답과 카드. 과거·예보·배치 분석. 도구 하나 추가로 새 자료를 붙일 수 있다. 지시문을 PR 로 리뷰한다.
- 감수하는 것: 도구 왕복만큼 답이 늦어진다 (실측 3~6초, 과거 조회는 외부 API 시간만큼 더). 메시지당 토큰이 는다. 숫자 검사는 측정 단위가 붙은 숫자만 보는 그물이라 모든 문장의 사실성을 증명하지 않는다.
- OpenAI 호환 경로는 도구 없이 같은 지시문과 미리 담은 자료(현재·덕장·배치·예보)로 답하고 과거 기간 분석은 하지 않는다.
- 과거 날씨는 기상청 구룡포 AWS(816)의 정각 값을 기간에 맞춰 1~12시간마다 받아 쓰고, 예보는 기상청 단기예보(약 3일)를 더한다 (2026-10-09 실호출, [기록](../../research/api-tests/2026-10-09-kma-history.md)). E-UM 통계 API 는 유해물질만 주고 기온·습도·풍속은 받지 않는다 ([기록](../../research/api-tests/2026-10-09-eum-stats-hour.md)). 기상청 키가 없으면 이 덕장의 배치 기록(배치가 진행 중일 때만 30분마다 쌓임)만 쓰고, 그 한계를 도구 결과에 적는다.
- 되돌리려면: `createLiveChat` 에서 도구 세션을 열지 않고 `--mcp-config` 를 빼면 도구 없는 설명으로 돌아간다. 저장 형식은 바뀌지 않았다 (0006 순서 불필요).
