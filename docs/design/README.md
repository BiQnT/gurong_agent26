# 설계 문서

최종 확인: 2026-10-04

**"현재 이렇게 되어 있다"만 적는다.** "왜 그렇게 정했나"는 [결정 기록](../decisions/)에.

서술형 문서는 낡기 쉬우므로 최소로 유지한다:

- 코드를 보면 알 수 있는 것은 적지 않는다
- 각 파일 맨 위에 **마지막 확인일**을 적는다
- 코드를 바꾸는 PR에서 이 폴더가 틀려지면 **같은 PR에서** 고친다

## 파일

- [backend.md](backend.md): 채팅 백엔드의 흐름과 프론트엔드가 쓰는 API 계약
- [프론트엔드 구조](frontend.md): 역할별 UI와 US-1·2·3의 컴포넌트, 상태, 저장 및 서버 연동 경계
- [계정·작업 API](workspace-api.md): 인증, 덕장, 초대, 역할, 공유 기록과 응답
- [채팅 API 계약](chat-api.md): 요청·응답, 처리 단계, 중단, 오류 처리

아이디어별 설계는 확정 전까지 각자 브랜치의 `ideas/NNN-<slug>/README.md`에 둔다.
확정된 하나만 여기로 승격한다.
