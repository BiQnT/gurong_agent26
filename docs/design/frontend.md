# 프론트엔드와 서버

최종 확인: **2026-10-04** · React·TypeScript·Vite · [관측·채팅 계약](chat-api.md) · [계정·작업 계약](workspace-api.md)

## 화면과 책임

`WorkspaceGate`가 세션 복원, 로그인/가입, 초대 검증/수락, 덕장 등록을 연결한다. 계정·덕장 키가 바뀌면 작업 화면을 새로 마운트하므로 이전 사용자의 대화·진행 중인 요청·열린 승인 창이 다음 화면으로 섞이지 않는다.

운영자는 로그인하면 AI 도우미(첫 화면에 오늘의 관측 포함)가 먼저 보이고, 오늘의 덕장(`OwnerHome`), 건조 기록, 작업 안내, 덕장·팀 관리를 오간다. 근로자는 `WorkerHome`에서 안내 언어, 할 일·지난 안내, 본인 응답을 확인한다. 역할은 서버가 반환하는 덕장 소속을 따르며 UI에서 선택해 권한을 얻지 않는다.

| 파일 | 책임 |
| --- | --- |
| `src/App.tsx` | 역할별 화면·메뉴·덕장 선택 조합 |

| `src/components/WorkspaceGate.tsx` | 최초·재방문·초대·등록 분기 |
| `src/components/workspace/` | 인증 폼, 지도 핀, 덕장 수정, 초대와 팀 관리 |
| `src/components/OwnerHome.tsx`, `WorkerHome.tsx` | 역할에 따른 주요 행동과 상태 |
| `src/lib/workspace.ts` | 계정·덕장·팀·작업 HTTP 클라이언트와 타입 |
| `src/hooks/useChat.ts` | 대화 저장·요청·취소·재시도 |
| `src/hooks/useLiveObservations.ts` | 덕장 관측·장비 선택·재조회 |
| `src/lib/operations.ts` | 승인 상태·집계·공유 데이터·충돌 재시도 |

화면은 비밀키와 원천 서비스 URL을 다루지 않는다. 계약 변경 시 클라이언트 타입·검증과 서버를 함께 수정한다. `VITE_API_BASE_URL`이 전체 애플리케이션 API의 교체 지점이다.

## 저장과 동시 작업

계정·소속·초대·작업은 서버 저장소(공유 SQLite 또는 로컬 파일, [서버 구조](backend.md))에 보관한다. 대화는 `haepung.conversations.v3:{userId}:{siteId}`, 선택한 덕장은 `haepung.site.v1:{userId}`, 관측소 선택은 `haepung.selected-device.v2:{siteId}`에 저장한다. 예전 시연 localStorage를 자동 이관하지 않는다.

작업 읽기는 `{data,revision}`이다. 운영자 변경은 최신 상태를 읽어 변환하고 같은 revision으로 저장한다. 충돌이면 다시 읽고 제한된 횟수 내에서 재적용한다. 근로자 응답은 별도 서버 경로로 사용자와 시각을 부여한다. 저장 성공 전에 창을 닫거나 성공 메시지를 표시하지 않는다. 10초 재조회와 포커스 복귀로 다른 사용자의 응답을 갱신한다.

운영자는 실제 질문에 원문 답변을 남긴다. 답변은 작성자·시각을 기록하며 중복 재전송이 새 기록을 만들지 않는다. 근로자는 자신의 질문 아래에서 확인한다.

근로자의 확인·완료는 본인의 userId로 계산한다. 다른 근로자의 완료가 내 할 일을 숨기지 않으며 배치 종료도 유발하지 않는다. 작업 도중 덕장을 바꿔 이전 응답이 뒤늦게 덮어쓰는 경우를 요청 식별과 마운트 경계로 방지한다.

## 실제 관측과 대기 경험

등록한 덕장과 장비 간 거리를 계산하고 가까운 최근 자료를 선택한다. 현재/과거/결측 상태와 원천 측정 시각을 유지하고, 관측에 확인 사항이 붙으면 함께 보여 준다(시간대 설정은 [chat-api.md](chat-api.md#실행과-환경-설정)). 관측 새로고침 시각이 원천 시각을 대신하지 않는다. 자동 재조회(탭이 보일 때 5분마다)는 화면 표시용이다. 배치 기록에 30분마다 쌓는 일은 서버의 [수집기](backend.md#수집기)가 화면과 무관하게 한다.

배치에 관측을 기록하려면 현재 상태, 실제 경과 30분 이내, 필수값·시각 유효, 미확인 원자료 조건 없음 등을 통과해야 한다. 운영자의 "현재 관측값 기록"과 수집기가 같은 기준을 쓴다. 적합 등급은 검증된 기준이 없어 생성하지 않는다. GPT 응답의 구조화된 카드도 모델이 생성하지 않는다.

AI 요청은 요청 전달 → 서버 응답 대기 → 응답 형식 확인을 표시한다. 서버 내부 진행률을 추정하지 않으며 최종 답변을 한 번에 추가한다. 취소된 응답은 무시한다.

## 스타일과 접근성

중성 팔레트와 공통 버튼을 유지한다. 공통 CSS와 역할별/워크플로우별 CSS를 분리한다. 폰 화면(900px 이하)은 하단 탭으로 화면을 옮기고 대화 목록·설정은 메뉴(☰)에 둔다. 키보드가 올라와 화면이 낮아지면(560px 이하) 글을 쓰는 동안 하단 탭을 숨긴다. 손가락 화면(`pointer: coarse`)은 입력 글자 16px(iOS 확대 방지), 버튼 36~40px 이상이다. 단일 열 카드, 충분한 버튼 높이, 입력 레이블, 폼 오류, 비밀번호 표시, 복사 실패 대안, 지도 권한 거부 시 좌표 입력을 제공한다.

대화상자는 포커스를 관리하고 요청 중 닫기를 제한한다. `MotionConfig reducedMotion="user"`와 `prefers-reduced-motion`을 유지한다. 지도는 실제 위치를 명시적으로 확인해야 저장할 수 있고, 지도를 못 불러와도 좌표로 등록할 수 있다.

## 검증과 후속 범위

`npm test`는 서버 인증·권한·초대·충돌·응답과 관측·집계·요청 계약을 확인한다. `npm run build`는 브라우저·서버 타입 검사와 배포 빌드, `npm run format:check`는 코드 형식을 검사한다. 실제 API 호출 기록은 [2026-10-04 기록](../../research/api-tests/2026-10-04-eum-key.md)에 있다.

Safari 제어가 `Computer Use was not approved to use Safari`로 거절되어 실제 Safari 화면·터치·키보드 검증은 수행하지 못했다. 타입·API 테스트를 브라우저 실증으로 간주하지 않는다.

이메일 확인/재설정, 경보·쿨다운, 자유 문장 번역과 외부 메시징은 별도 연결이 필요하다. 서버 배포와 공유 DB, 30분 수집은 [서버 구조](backend.md)에 있다. 초대 링크는 만든 화면의 주소로 만들어지므로 로컬(127.0.0.1)에서 만든 링크는 다른 기기에서 열리지 않는다.
